# Normal closeout preservation contract — unchanged input schema

Only lifecycle.py, remote.py and new preservation controls differ from frozen8a720 candidate. No config/input field, stage/counter cap, actor, provider deadline, expected hardware, source core/driver, Collector, transport, worker, run.sh or service was changed. The parent frozen manifest is retained untouched; tests pin a synthetic manifest in external fixtures. Root must regenerate actual package/component refs for deployment after review.

Remote poll now reads the original native TransferSpool binding, exact seven-field transfer config, complete sequential reservation prefix and accounting cursor while holding the already-existing spool lock. No constructor, ACK reconciliation or spool deletion occurs during poll. It uses native TransferSpool._manifest for codec/group/manifest/seal validation and validates real sealed dictionary shapes: checkpoint={item,index}, final={manifest}. Boolean sealed is refused. Every reserved generation is returned, including missing/unsealed groups; groups lacking an original reservation are refused. SHA-pinned incoming and retained guest ACK bytes must agree. Same native deadline, source, codec and cumulative allowance remain.

Poll retains existing output schema dams-compute-live-poll-v1, adding reservation_generations and spool_high_water{schema,sequence,previous_sha256,reserved_bytes,history_sha256}. Each sealed row includes group_sha256, config_sha256, attempt and exact ack_sha256 (null until an ACK is applied), alongside previous manifest/seal/case/kind/day fields. It is an observed native prefix, not a new allowance or a full scientific gate.

Normal closeout requires exact equality of reserved generation IDs, sealed IDs and original local Collector ACK IDs. Unsealed/missing history, missing/unapplied ACK, guest/local ACK discrepancy or stale receipts refuse active DELETE. For every ACK, both current original Collector restoration descriptors and durable receipts are re-read; source/assignment/config/codec/seal/group/gate/restorationID/counter floor and distinct physical file identities are checked using existing gates. Full SQL/scientific validation is inherited from the already accepted Collector receipts; no Model or new gate is substituted.

After that, original terminal capture must finish both physical file copies and closed-byte SHA/length readbacks for ALL native outputs, including failed-case forensic sidecars. Exact stage case_inventory rows must match the externally pinned assignment. A stopped stage requires the real source/driver/spec/inventory-bound case_census and disjoint complete/valid-latest-checkpoint/failed/unstarted records covering the literal inventory; complete cases need accepted final raw and latest CP classifications need the exact accepted CP/index/day/pointer. A successfully complete stage uses its complete source-bound manifest/expected rows/output hashes and accepted final-case ACKs. Union coverage must equal the original assignment. This does not require every case to complete: failed/unstarted/censored cases remain explicit; four-layer/full-study/science completion stay false.

A final fresh poll must equal the captured original reservation/ACK view. ACK/receipt and census byte versions, terminal raw file identities/ancestors and receipt rosters are checked again immediately before native VM/disk DELETE. Normal preservation failure records uncertainty, keeps all original holds and does NOT dispatch an active DELETE. The already-fixed provider absolute expiry remains, without extension; root must schedule scientific stop/transfer/readback early enough. An absolute provider timeout cannot be called successful preservation.

No new automatic recovery/retry/discard was introduced. Terminal-copy directories remain exclusive: after a failed partial copy/closure, root must retain/reconcile that attempt, not overwrite it or freshen the actor/known head. Root-owned original source launch-failure cleanup remains unchanged (only normal closeout repaired here).
