# Scientific specs and bounded execution (schema 2)

The source model retains the 0.1.0 behavioral equations. The current core source hash identifies the expanded execution, state serializer, event bounds and recovery path. The published `paper-2026-10-08` release remains the immutable historical source and full-study evidence; changing the current checkout never changes that release's history.

`python -m dams_sim pipeline --spec SPEC --scale PEOPLE --output PATH` and `python -m research_tools.pipeline` invoke the same pipeline. The repository's one-line wrapper prepares dependencies; this Python entry does not create cloud resources or authorize spending. `--runtime-limits FILE` accepts private execution limits separately from the scientific spec. The default Python spec is `validation` with 24 people. The wrapper can explicitly choose its documented safe scale.

| Spec | Days | Independent primary worlds | Scope |
|---|---:|---:|---|
| historical-full-study | 60 | historical 32–64 pilot-fixed | Original fixed 120-person inventory and original driver path; exact old source requires the published historical release |
| full-study | 60 | 32–64 pilot-fixed | All five policies, three stylized record backends, two cadences, analytical, attacks, screening, structural/context, scale/shock and synthetic recovery stages |
| validation | 30 | 2 | Explicit small design exercising all stages and output/recovery interfaces; cannot replace formal full-study precision |

| scale-confirmation | 30 | Fixed 8 through 1 million; fixed 2 at 10 million | Five policies, daily central records. No new pilot or post-outcome sample increase. Ten-million cases are explicitly exploratory and are not pooled with smaller scales |

Scale means actual individual people in every executed dynamic stage, including synthetic recovery. Guilds, sites and team size remain independent parameters in the versioned preset; people are not validators. Full and validation recovery use the preset's actual population/horizon and four patterns, with disjoint observation, prediction and holdout world ranges. Holdout values never select the training candidate. Raw complete states are retained for each new pipeline case, unlike the historical recovery's four-pattern-only evidence.

Attacks have budgets 2/120 and 8/120 hour-equivalents per person per day, the same fixed 0.5 actor cohort, and each policy's matched unattacked control. This preserves comparable per-person declared attack costs when scale changes. It does not establish equal realized productive opportunity cost across policies.

Each spec manifest records every effective field and the exact scientific-spec SHA. Case IDs hash all scientific Config fields while excluding four execution-limit fields; complete raw configurations still record those limits. Paired policies/backends share stable world/entity/event/random-process IDs. Completion order and worker count never select or reorder the study sample. Cross-scale repetitions do not add independent worlds to a single-scale estimate.

## Runtime limits

Unknown fields, wrong types, nonfinite values and unsupported private provenance keys fail. Runtime schema 1 fields are `version`, `workers_auto`, `max_workers`, `cpu_budget`, `memory_budget_bytes`, `per_world_rss_bytes` (optional), `max_events`, `max_output_bytes`, `batch_max_output_bytes`, `min_free_disk_bytes`, `world_timeout_seconds`, `deadline_utc`, `checkpoint_interval_days`, `checkpoint_interval_seconds`, `max_retries`, and `provenance`. Permitted provenance is instance ID, machine type, zone, project hash, packaged commit, image digest, environment and stable task hash. Private project names, billing and budgets are rejected.

All byte fields are bytes. Config `max_rss_mb` and recorded RSS measurements use MiB; Config `max_output_mb` uses decimal MB. The scheduler converts these units explicitly. `max_events` is the bound on unique daily work creation `people × days`, consistent with Config. The manifest additionally records a conservative `(12N+4G) × days` operation bound including votes, claim creation, review, appeal and commitments. These are distinct units, not a claim of measured CPU instructions. The Config event-validation ceiling is now 10^12, but its default remains two million; ten million × thirty days still requires an explicit bound of at least 300 million plus sufficient RAM, disk and time. No guard removes people, shortens days or disables mechanisms.

The RAM preflight estimate is `64 MB + N × (12000 + 400 × days)` bytes, including topology, day snapshots/heaps, retained event IDs/delays, checkpoint restoration and serialization sorting. A single-state/output estimate is `1 MB + N × (2200 + 40 × days)` bytes. Four copies are reserved for latest/previous checkpoints, final state and a temporary write. These conservative design estimates are not hardware certification or measured scale performance. Actual measurements and failure records remain authoritative. A new world is admitted only within CPU, aggregate reserved RAM, world/batch output and free-disk bounds. The absolute deadline is persisted and cannot be extended on resume. Output/RSS/time limits in the initial frozen Config also cannot change when continuing the same output directory; worker count and whole-machine envelope may change without changing a sample.

A fresh process executes each independent case, with BLAS/OpenMP thread counts capped at one. This avoids retaining another world's RSS high-water. Day-boundary atomic checkpoints have immutable `checkpoint-day-NNNNNN.json` files and an atomically replaced `checkpoint-index.json` identifying two generations by source/config SHA, exact file SHA and completed day. Directory and file content are fsynced. On interruption, only checked source/config-compatible state resumes. A checkpoint is not a completed world. TERM requests a completed-day save and nonzero exit; a hard kill can lose the current unfinished day and resumes from the last valid periodic checkpoint. Very long days or serializations can exceed termination grace, so the latest prior checkpoint remains the recovery guarantee, not the shutdown notification.

Attempt directories and failure sidecars are preserved. A bounded retry uses the same case ID and random keys, retains measured elapsed world-attempt time, and shares the original absolute batch deadline. Cloud cache reuse requires retained cloud instance/type/zone and matching project/package/environment/task identities; local cached evidence cannot acquire a cloud execution label. Complete reuse verifies source, driver, exact Config, Config digest, case ID, full output roster, every recorded SHA, population and horizon. A process lock prevents two coordinators from writing the same output. The cloud wrapper separately owns persisted cost accounting, upload/download validation, VM identity and cleanup; uploading a checkpoint does not prove scientific completion.

The pipeline reports success only after its declared stage roster, inventories, completed raw outputs, analysis inputs and source guard pass. It writes `spec_manifest.json`, `protocol.json`, stage `case_inventory.json`/`case_references.json`/`world_summary.csv`/`manifest.json`, central `cases/CASE/attempt-NNN/`, `case_statuses.json`, `analysis/claims.json`, and `report.md`. The report is a data report; publication figures require the compatible v2 analyzer. The old analyzer's fixed inventory and denominators cannot be used for scaled data.
